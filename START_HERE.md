# Aru — сайт косметологического кабинета в Астане

Полный проект с русским и казахским интерфейсом, онлайн-записью, базой, админкой и Telegram. WhatsApp — дополнительный платный канал, его можно оставить выключенным. Название Aru — предложенная заглушка, его можно заменить. Фото мастера, реальные сертификаты, адрес и контакты не выдуманы: для них оставлены места. Отзывы и цены подписаны как примеры.

## 1. Архитектура и расходы

**React + TypeScript + Vite** — интерфейс. **Cloudflare Workers** — сервер. **Cloudflare D1** — SQLite-база в облаке. **Drizzle** — описание таблиц и миграции. **Telegram Bot API** — уведомления маме. **Twilio WhatsApp API** — согласованные сообщения клиенту. **Cloudflare Cron Trigger** — проверка очереди каждые 5 минут. На компьютере тот же сервер и локальная SQLite работают через Wrangler, отдельно устанавливать базу не нужно.

Выбран этот стек, потому что сайт, база и cron настраиваются в одном Cloudflare-аккаунте; для небольшого кабинета он проще, чем несколько отдельных сервисов. Сервер содержит только Web API и SQL, его рабочий пакет небольшой. Next.js и Supabase здесь не нужны.

Что оплачивается (проверено 1 октября 2026 года):

| Workers Free          | Бесплатно в пределах 100 000 запросов в день, с лимитом CPU 10 мс на вызов. Для стабильной работы при превышениях можно перейти на Workers Paid от $5/месяц. |
| D1 Free               | Включены 5 млн прочитанных строк/день, 100 тыс. записанных строк/день и 5 ГБ общего хранения.                                                                |

Например, 100 напоминаний и 10 отмен — 110 исходящих сообщений, комиссия Twilio $0,55 плюс плата Meta, возможные входящие сообщения и налоги. Это не итоговая цена для Казахстана: точную сумму смотрите в калькуляторе Twilio перед пополнением. Полностью бесплатные автоматические WhatsApp-уведомления проект не обещает. Бесплатные квоты Cloudflare нужно контролировать; платный план — разумный вариант для рабочего кабинета.

Официальные источники: [Workers: тарифы](https://developers.cloudflare.com/workers/platform/pricing/), [D1: тарифы](https://developers.cloudflare.com/d1/platform/pricing/), [WhatsApp: тарифы Twilio](https://www.twilio.com/en-us/whatsapp/pricing). Vercel Hobby не выбран для сайта бизнеса: [правила Hobby](https://vercel.com/docs/plans/hobby).

### Как сохраняется запись

1. Браузер отправляет только ID процедур, имя, телефон, время и согласие. Сервер берёт цены и длительность из `data/procedures.json`, не доверяет сумме в браузере.
2. Сервер проверяет рабочие окна, выходные, горизонт 60 дней и минимальное время до визита — 30 минут. Вся зона времени — `Asia/Almaty`, независимо от настроек компьютера.
3. Визит и уборка после него занимают уникальные 15-минутные отрезки в таблице `occupancy`. Одна транзакция D1 `batch` сохраняет запись, все отрезки и задачи уведомлений. Если хоть один отрезок занят, вся транзакция откатывается. Две одновременные записи с пересечением не пройдут.
4. Цены и названия сохраняются снимком. Изменение прайса не меняет уже оформленные записи.
5. Повтор того же запроса после потери ответа возвращает исходную запись. Секретная ссылка подтверждения использует 256-битный токен в `#fragment`, а в базе хранится только его хеш. Не пересылайте такую ссылку посторонним: она даёт доступ к сведениям конкретной записи.

### Напоминания, отмена и отсутствие дублей

- При новой записи Telegram-задача создаётся одновременно с записью. Сервер пытается отправить её сразу, а оставшиеся ожидающие задачи подбирает cron.
- Напоминание получает срок `начало визита − 3 часа`. Если записались позже этого срока, срок задачи — сейчас; сервер отправляет сообщение сразу после оформления либо на ближайшем проходе cron. При аварии доставка может задержаться. Проверка каждые 5 минут означает обычную погрешность до 5 минут.
- Напоминания для уже начавшихся визитов пропускаются.
- Два cron захватывают задачу атомарным SQL: отправить её сможет только один процесс. У каждой записи только одна задача каждого вида.
- Telegram сначала показывает «Да, отменить» и «Оставить запись». Подтверждение действует 5 минут, одноразовое; сервер проверяет секрет webhook, личный чат и ID владельца.
- Отмена в админке также требует подтверждения. Она освобождает отрезки. WhatsApp-задача создаётся в режиме disabled, если платный канал выключен или клиент не дал отдельное согласие; тогда об отмене нужно сообщить лично или по телефону. Повторная отмена не создаёт второе сообщение.
- Если отмена совпала с уже отправляемым напоминанием, статус кратковременно станет `cancel_pending`. Завершение отмены ждёт ответа или тайм-аута запроса (обычно до 12 секунд). Затем слот освобождается и уходит сообщение об отмене. Если процесс оборвался, cron завершит отмену после восстановления зависшей задачи, не ранее чем через 2 минуты.
- Пока запись уже `cancelled`, новые напоминания не захватываются. Сообщение, которое провайдер успел принять до отмены, невозможно отозвать: следом идёт отмена.
- Абсолютная гарантия «ровно один раз и обязательно доставлено» невозможна для внешнего HTTP API при потере ответа. Здесь выбран приоритет **не создавать дубликаты**. После неизвестного ответа (`timeout`, сбой процесса, HTTP 5xx) задача получает `uncertain`; после явного отказа — `failed`. Автоповтора нет. Мама видит проблему в админке, вы проверяете журнал Twilio/Telegram и связываетесь с клиентом вручную. Это также относится к Telegram.
- `sent` означает, что сервис принял запрос. Фактическое состояние WhatsApp `delivered/read/failed` обновляет подписанный callback Twilio; смотрите его в админке. При `failed/uncertain` само бронирование остаётся сохранено.

## 3. Запуск на компьютере — сначала без внешних сервисов

1. Установите **Node.js 24 LTS** с [nodejs.org](https://nodejs.org/). Используйте поддерживаемый LTS, не старую версию 18. Установка npm входит в Node. Установите [Visual Studio Code](https://code.visualstudio.com/).
2. Распакуйте архив в обычную папку, например `C:\Projects\astana-beauty`. Откройте эту папку в VS Code: File → Open Folder. Затем Terminal → New Terminal. Все следующие команды вводятся **в этой папке**, где лежит `package.json`.
3. Проверьте установку:

   ```powershell
   node -v
   npm -v
   ```

4. Установите библиотеки:

   ```powershell
   npm ci
   ```

5. Создайте локальное окружение:

   ```powershell
   Copy-Item .env.example .dev.vars
   ```

   Откройте `.dev.vars`. Для локальной проверки поставьте `BOOKING_ENABLED=true`, оставьте `NOTIFICATIONS_ENABLED=false`. Придумайте `ADMIN_PASSWORD` длиной от 16 символов. Замените все значения `replace-...`. Для каждого секрета отдельно выполните команду и скопируйте результат:

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

   Разные случайные значения нужны для `SESSION_SECRET`, `CRON_SECRET`, `TELEGRAM_WEBHOOK_SECRET`. `SITE_URL` локально — `http://127.0.0.1:5173`. Пустые поля Telegram/Twilio пока можно не заполнять. Файлы `.dev.vars` и `.env` исключены из Git.

6. Создайте таблицы в **локальной** базе:

   ```powershell
   npm run db:local
   ```

7. Запустите сайт:

   ```powershell
   npm run dev
   ```

   Откройте [локальный сайт](http://127.0.0.1:5173). Не закрывайте терминал, пока пользуетесь сайтом. Выберите процедуры, дату, время и оформите тестовую запись. Поскольку внешние сервисы отключены, ничего не отправится, а подтверждение честно сообщит об этом.

8. Админка: [локальная админка](http://127.0.0.1:5173/admin). Введите `ADMIN_PASSWORD` из `.dev.vars`. Выберите дату. Очистив поле даты, получите все записи с постраничным просмотром. Попробуйте отменить тестовую запись.
9. Остановить сервер: нажмите `Ctrl+C`. Для проверки проекта:

   ```powershell
   npm run typecheck
   npm test
   npm run build
   ```

   Тесты используют Node SQLite и отдельную базу в памяти; клиентские данные не затрагиваются. После изменений `data/`, `locales/`, фото и CSS нужна новая сборка и деплой.

## 4. Cloudflare: аккаунт, облачная база и первый деплой

1. Создайте бесплатный аккаунт на [Cloudflare](https://dash.cloudflare.com/sign-up), подтвердите email. Пока не нужно покупать домен.
2. В терминале проекта войдите в аккаунт:

   ```powershell
   npx wrangler login
   ```

   Откроется браузер. Разрешите доступ Wrangler к **вашему** аккаунту.

3. Создайте облачную базу:

   ```powershell
   npx wrangler d1 create astana-beauty-db
   ```

   Из ответа скопируйте `database_id`. Откройте `wrangler.jsonc` и замените `00000000-0000-4000-8000-000000000000` вашим ID. `binding` оставьте `DB`, `database_name` — `astana-beauty-db`. Это ID базы, не пароль.

4. Создайте таблицы в облаке:

   ```powershell
   npm run db:remote
   ```

   В команде есть `--remote`: она применяет миграции только к облачной базе. Локальные тестовые записи туда не переносятся. Готовая миграция входит в проект; `db:generate` для первого запуска не нужен.

5. Соберите и опубликуйте:

   ```powershell
   npm run build
   npm run deploy
   ```

   Сохраните HTTPS-адрес вида `https://astana-beauty.ВАШ-АККАУНТ.workers.dev`. У каждого аккаунта свой адрес; не вставляйте адрес чужого предпросмотра.

6. В Cloudflare Dashboard: Workers & Pages → `astana-beauty` → Settings → Variables and Secrets. Добавьте значения из таблицы ниже. Секреты выбирайте как **Secret**, не как обычный открытый текст. Добавляйте только настоящие значения, не `replace-...`.

   | Имя                     | Значение                                                            |
   | ----------------------- | ------------------------------------------------------------------- |
   | `BOOKING_ENABLED`       | Пока `false`; откроете запись после проверки                        |
   | `NOTIFICATIONS_ENABLED` | `true` после подключения Telegram; пока `false`                                                        |
   | `SITE_URL`              | Ваш полный HTTPS-адрес, без завершающего `/`                        |
   | `ADMIN_PASSWORD`        | Ваш уникальный пароль, от 16 символов, Secret                       |
   | `SESSION_SECRET`        | Случайная строка от 32 символов, Secret                             |
   | `CRON_SECRET`           | Другой случайный секрет, Secret                                     |
   | `TELEGRAM_*`            | Добавьте после настройки бота ниже; токен и webhook-secret — Secret |
   | `TWILIO_*`              | Добавьте после настройки WhatsApp; auth-token — Secret              |
   | `TURNSTILE_*`           | Добавьте перед публичным открытием формы, secret-key — Secret       |

   Для секрета можно использовать и CLI: `npx wrangler secret put ADMIN_PASSWORD` — он попросит значение, без включения его в команду. Задавайте секреты для Worker `astana-beauty`, не для другого проекта. Dashboard может попросить Deploy после изменения окружения — подтвердите и дождитесь активного деплоя.

7. Проверьте `/admin`: вход с вашим паролем, посторонний посетитель не получает список через API. Пароль не отправляется браузеру из конфигурации. Сессия HttpOnly/SameSite/HTTPS, на 8 часов; изменение `SESSION_SECRET` завершает существующие сессии.
8. В Settings → Triggers / Cron Triggers проверьте `*/5 * * * *`. Он уже указан в `wrangler.jsonc`, отдельно создавать второй cron не нужно. Cron работает в UTC, но запускается каждые 5 минут; сама дата визита хранится и отображается в `Asia/Almaty`. Распространение новой настройки cron может занять до 15 минут. [Документация Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/).
9. После обновлений:

   ```powershell
   npm run typecheck
   npm test
   npm run build
   npm run deploy
   ```

   Если меняли структуру таблиц — сначала `npm run db:generate`, осмотрите новую SQL-миграцию и примените `npm run db:remote`. Уже применённые миграции не редактируйте. Изменение прайса не требует миграции.

Приватный предпросмотр Sites, выданный в чате, нужен для просмотра дизайна. Его внешний Telegram webhook и callback WhatsApp закрыты авторизацией Sites; для реальных клиентов используйте публичный Cloudflare-адрес по этой инструкции. В приватном предпросмотре приём записей и отправка сообщений выключены до настройки владельцем.

## 5. Telegram для мамы

1. В Telegram откройте [@BotFather](https://t.me/BotFather). Отправьте `/newbot`, выберите имя и username, заканчивающийся на `bot`. Полученный токен запишите в `TELEGRAM_BOT_TOKEN` файла `.dev.vars` и Secret с тем же именем в Cloudflare. Токен даёт управление ботом, его нельзя публиковать.
2. Мама со своего аккаунта должна открыть нового бота и нажать **Start**. Бот не может первым начать личный диалог.
3. Пока webhook не установлен, выполните:

   ```powershell
   node scripts/telegram.mjs ids
   ```

   В выводе найдите сообщение мамы и скопируйте `TELEGRAM_CHAT_ID` и `TELEGRAM_OWNER_ID` в `.dev.vars` и Cloudflare. Для личного чата эти значения обычно совпадают. Не используйте ID группы: отмена настроена на личный чат и конкретного пользователя.

4. В `.dev.vars` и Cloudflare задайте одинаковый случайный `TELEGRAM_WEBHOOK_SECRET`, используя только буквы, цифры, `_` или `-` (сгенерированный hex подходит).
5. После публичного Cloudflare-деплоя зарегистрируйте callback, подставив свой адрес:

   ```powershell
   node scripts/telegram.mjs register https://astana-beauty.ВАШ-АККАУНТ.workers.dev
   node scripts/telegram.mjs status
   ```

   Скрипт читает токен из `.dev.vars`, поэтому не нужно вставлять его в URL браузера или сохранять в истории команды. Проверка использует `X-Telegram-Bot-Api-Secret-Token`, разрешены только callback-события.

6. Для бесплатного режима включите `NOTIFICATIONS_ENABLED=true`, оставьте `WHATSAPP_ENABLED=false`. Telegram работает независимо от WhatsApp. Создайте **новую** тестовую запись: мама должна получить имя, телефон, процедуры, сумму, дату и время. Старые задачи режима `disabled` не отправляются задним числом.
7. Нажмите «Отменить запись». Первое нажатие ничего не отменяет: появятся «Да, отменить» и «Оставить запись». Проверьте оба варианта. После подтверждения слот снова доступен. WhatsApp-сообщение отмены отправляется только при включённом платном канале и отдельном согласии клиента.

Если `ids` сообщает, что включён webhook, ID уже можно найти в прежней настройке. Не используйте `getUpdates` и webhook одновременно. Если бот не отвечает, запустите `status`, проверьте публичность HTTPS-адреса, `TELEGRAM_CHAT_ID`, `TELEGRAM_OWNER_ID` и совпадение webhook-secret. [Telegram Bot API](https://core.telegram.org/bots/api#setwebhook).

## Бесплатный режим и тестовая запись

Для работы без платных WhatsApp-сообщений используйте `NOTIFICATIONS_ENABLED=true` и
`WHATSAPP_ENABLED=false`. Новые записи поступают мастеру в Telegram. Клиент видит
подтверждение на сайте и сохраняет дату и время самостоятельно. Об отмене мастер
сообщает клиенту лично или по телефону. Никаких запросов к Twilio при выключенном
канале сервер не выполняет, даже если ключи Twilio уже заполнены.

`BOOKING_ENABLED=false` оставляет приём клиентов закрытым. Для проверки войдите в
`/admin`, нажмите **Тестовая запись** и пройдите обычную форму. Доступ к тесту
требует админской сессии; имя автоматически получает метку `[ТЕСТ]`, WhatsApp
всегда выключен. Тест занимает настоящие интервалы базы, поэтому после проверки
отмените его через Telegram или админку. Старые записи не получают согласие на
WhatsApp автоматически при последующем включении канала.

После обновления проекта с предыдущей версии выполните `npm run db:local` и
`npm run db:remote`: новая миграция добавляет отдельное время согласия на WhatsApp
и сохраняет существующие записи. Затем выполните сборку и деплой.

## 6. WhatsApp через Twilio

### Тестовый Sandbox и рабочий отправитель

1. Создайте аккаунт на [Twilio](https://www.twilio.com/try-twilio). В Console возьмите `Account SID` (`AC...`) и `Auth Token`. Добавьте их как `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN` в `.dev.vars` и в Cloudflare Secrets.
2. Для знакомства откройте Messaging → Try it out → Send a WhatsApp message / Sandbox. Отправьте со своего WhatsApp `join ...` на указанный Twilio номер. Участником Sandbox должен стать каждый тестовый получатель. Sandbox предназначен для проверки, не для клиентов кабинета. Его шаблоны заранее заданы; готовые RU/KZ шаблоны этого проекта проверяйте на зарегистрированном рабочем отправителе. [Sandbox: ограничения и тестирование](https://www.twilio.com/docs/whatsapp/sandbox).
3. Для работы пополните Twilio и откройте Messaging → Senders → WhatsApp Senders → Self Sign-up. Пройдите связь с Meta Business Portfolio / WhatsApp Business Account и проверку номера, которым будет пользоваться кабинет. Лучше выбрать отдельный рабочий номер; следуйте текущей процедуре Twilio, особенно если номер уже связан с приложением WhatsApp. Могут потребоваться сведения о бизнесе и проверка Meta. Это действие владелец аккаунтов проходит сам. [Self Sign-up](https://www.twilio.com/docs/whatsapp/self-sign-up).
4. В `TWILIO_WHATSAPP_FROM` укажите `whatsapp:+7...` с **одобренным номером отправителя**. Номер `whatsapp:+14155238886` в `.env.example` — пример для Sandbox, его нельзя оставить для рабочего кабинета.

### Создание четырёх шаблонов

1. Console → Messaging → Content Template Builder. Создайте четыре текстовых шаблона: `aru_reminder_ru`, `aru_cancel_ru`, `aru_reminder_kk`, `aru_cancel_kk`. Для каждого выберите правильный язык; русский — `ru`, казахский — `kk`.
2. Тексты ниже — ваши редактируемые примеры, не цитаты Twilio:

   **Напоминание, RU:**

   ```text
   Здравствуйте, {{1}}! Напоминаем о вашей записи в кабинет Aru: {{2}}, время Астаны. Процедуры: {{3}}. Если планы изменились, свяжитесь с кабинетом. До встречи!
   ```

   **Отмена, RU:**

   ```text
   Здравствуйте, {{1}}! Ваша запись в кабинет Aru на {{2}}, время Астаны, отменена. Процедуры: {{3}}. Для выбора нового времени свяжитесь с кабинетом. Спасибо!
   ```

   **Напоминание, KZ:**

   ```text
   Сәлеметсіз бе, {{1}}! Aru кабинетіне жазылғаныңызды еске саламыз: {{2}}, Астана уақыты. Процедуралар: {{3}}. Жоспарыңыз өзгерсе, кабинетке хабарласыңыз. Кездескенше!
   ```

   **Отмена, KZ:**

   ```text
   Сәлеметсіз бе, {{1}}! Aru кабинетіне {{2}} күні, Астана уақыты бойынша жазылуыңыз тоқтатылды. Процедуралар: {{3}}. Жаңа уақытты таңдау үшін кабинетке хабарласыңыз. Рақмет!
   ```

3. Для примеров переменных поставьте: `1` = «Айгерим», `2` = «2 октября 2026 г., 14:00», `3` = «Ультразвуковая чистка». В казахском шаблоне примеры также должны быть на казахском. Категория — **Utility**, поскольку это сообщение о уже оформленном визите без рекламы. Итоговую категорию и согласование определяет Meta; дождитесь статуса Approved.
4. Из каждого шаблона скопируйте Content SID (`HX...`):

   ```dotenv
   TWILIO_REMINDER_RU=HX...
   TWILIO_REMINDER_KK=HX...
   TWILIO_CANCEL_RU=HX...
   TWILIO_CANCEL_KK=HX...
   ```

   Добавьте их в `.dev.vars` и в Cloudflare. В коде используются ContentSid и ContentVariables; Body не отправляется. Шаблоны позволяют напомнить о записи вне 24-часового окна диалога. [Отправка шаблонов](https://www.twilio.com/docs/content/send-templates-created-with-the-content-template-builder), [From без Messaging Service поддерживается](https://www.twilio.com/en-us/changelog/content-templates-messaging-services-optional).

5. В `SITE_URL` должен быть ваш публичный HTTPS-адрес. Сервер сам передаёт Twilio `StatusCallback` на `/api/twilio/status?id=...`; отдельно задавать callback для каждого сообщения в Console не нужно. Проверяется подпись Twilio с `Auth Token`, поддельный callback отвергается.
6. Включите `NOTIFICATIONS_ENABLED=true` и `WHATSAPP_ENABLED=true`, создайте новую запись с отдельной галочкой согласия на свой WhatsApp-номер и проверьте Messages Logs. Затем проверьте запись на казахском языке и отмену. Состояние `sent` без `delivered` ещё не доказывает доставку.

Согласие на сообщения входит в форму. Этот проект не отправляет рекламные рассылки. Напоминание содержит имя, дату, время и процедуры; сообщение отмены содержит те же сведения. По умолчанию повторное сообщение при неопределённом результате не отправляется — смотрите раздел об отсутствии дублей.

## 7. Защита от спама и настройки перед открытием

Уже включены серверные проверки, невидимое поле-ловушка, лимит 5 новых записей/час на IP и 3/день на номер, 8 попыток входа в админку за 15 минут, лимиты чтения слотов и подтверждений, проверка Origin для изменений, SQL-параметры, закрытый доступ к админским данным. Лимиты хранятся в D1 и не пропадают между серверными процессами.

Для публичной формы добавьте бесплатную проверку **Cloudflare Turnstile**:

1. Dashboard → Turnstile → Add widget. Выберите Managed и добавьте точный hostname вашего `workers.dev` или своего домена, без `https://`.
2. Добавьте Site Key как `TURNSTILE_SITE_KEY`, Secret Key как `TURNSTILE_SECRET_KEY` в окружение Worker. Для локальных проверок можно оставить оба пустыми или использовать отдельные тестовые ключи; не используйте рабочий ключ на другом домене.
3. Сервер проверяет не только результат, но hostname и action `booking`; одноразовый токен проверяется на сервере. После ошибок виджет обновляется. [Настройка Turnstile](https://developers.cloudflare.com/turnstile/get-started/).

Когда контакты, цены, тексты и Telegram проверены (WhatsApp можно оставить выключенным), задайте в облаке `BOOKING_ENABLED=true`. Перед этим заполните текст конфиденциальности реальными данными владельца, сроком хранения и контактом для запросов. В шаблоне нет медицинской анкеты; не собирайте диагнозы через поле имени.

## 9. Чек-лист тестирования перед первым клиентом

- [ ] `npm run typecheck`, `npm test`, `npm run build` проходят.
- [ ] Русский и казахский работают на главной, в форме, подтверждении и админке; тексты и контакты проверены владельцем.
- [ ] На телефоне шириной 390 px нет горизонтальной прокрутки; элементы можно нажать, браузерное увеличение текста не мешает.
- [ ] Выбор двух процедур правильно суммирует минуты и тенге. Удаление процедуры пересчитывает результат.
- [ ] Нельзя выбрать отключённую услугу, несуществующий ID, прошлую дату, выходной, обед или слот, не помещающийся до закрытия вместе с уборкой.
- [ ] Некорректный телефон, пустое имя, отсутствие согласия и невалидная Turnstile-проверка отклоняются.
- [ ] Оформите запись, откройте ту же дату в другом браузере — пересекающиеся времена недоступны.
- [ ] Откройте две формы до сохранения и отправьте на одинаковое/пересекающееся время — сохраняется только одна; вторая получает просьбу выбрать другое время.
- [ ] После перезагрузки сервер/браузер видят сохранённые записи. Они живут в D1, не в localStorage.
- [ ] Ссылка подтверждения показывает состав, дату и итог. Без секретного токена `/api/bookings/ID` не показывает личные данные.
- [ ] Без пароля `/api/admin/bookings` возвращает 401. После входа фильтры даты и статуса работают, страницы позволяют увидеть всю историю.
- [ ] Новая запись приходит маме в Telegram с верной суммой и временем Астаны. «Оставить запись» сохраняет её. «Да, отменить» отменяет и освобождает слот.
- [ ] Повторное нажатие отмены не создаёт новое сообщение. Чужой Telegram-аккаунт не может отменить запись.
- [ ] Отмена через админку также освобождает время и создаёт WhatsApp-сообщение.
- [ ] Поздняя запись (за 30 минут–3 часа) получает одно напоминание сразу. Для дальней записи — примерно за 3 часа. В админке есть `sent`, в Twilio — правильный получатель и `delivered`.
- [ ] Отмените запись до срока напоминания: напоминание не отправляется. Проверьте два последовательных запуска cron: дубля нет.
- [ ] Если отвалился ответ внешнего сервиса, появляется `uncertain`, повторной автоматической отправки нет. Если провайдер отказал, появляется `failed` и причина/ID доступны в подсказке админки.
- [ ] Секреты отсутствуют в Git/архиве, настоящий `.dev.vars` не загружен в репозиторий.
- [ ] В Cloudflare Logs нет `cron_requires_SITE_URL`, в Telegram `status` нет ошибок webhook.

На этапе разработки проверены 16 автоматических тестов: расписание, валидация услуг, SQL-откат пересечения, одновременные запросы, повтор запроса, отмена, очередь и отсутствие дублей, потеря ответа, гонка отмены, Telegram-подтверждение, админская сессия и подпись Twilio. Также выполнена запись через браузер, переключение RU/KZ и проверка мобильной ширины. Дополнительно проверены бесплатный режим, блокировка ранее созданных WhatsApp-задач, отсутствие отправки без согласия и защищённая тестовая форма. Настоящая отправка Telegram/WhatsApp требует ваших аккаунтов и одобренных шаблонов и проверяется по чек-листу после подключения.

## 10. Если что-то не работает

| Симптом                   | Что проверить                                                                                                                                                                  |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `npm` не найден           | Переоткройте VS Code после установки Node; выполните `node -v`, `npm -v`.                                                                                                      |
| `no such table: bookings` | Локально выполните `npm run db:local`, в облаке `npm run db:remote`. Проверьте ID базы.                                                                                        |
| Даты пустые               | Выходной, обед, слишком длинный набор процедур, 15 минут уборки или уже занятый день.                                                                                          |
| Запись не открыта         | В окружении `BOOKING_ENABLED` должно быть строкой `true`.                                                                                                                      |
| Админка требует настройки | Пароль от 16 символов, SESSION_SECRET от 32; заменены значения `replace-...`. Перезапустите локальный сервер после изменения `.dev.vars`.                                      |
| Нет Telegram              | Мама нажала Start? Правильные chat/owner ID? Webhook публичный? Одинаковый secret? Посмотрите `node scripts/telegram.mjs status`.                                              |
| `whatsapp_not_configured` | Заполнены Account SID/Auth Token/From и Content SID нужного языка? Старые неудачные задачи не перезапускаются автоматически; создайте новую тестовую запись после исправления. |
| Twilio ошибся             | Смотрите Messages Logs и код ошибки. Отправитель одобрен? Шаблон Approved? Номер клиента зарегистрирован в WhatsApp? В Sandbox получатель присоединился?                       |
| Cron не работает          | `SITE_URL` — публичный HTTPS origin, trigger существует, NOTIFICATIONS_ENABLED=true, настройка распространилась.                                                               |
| Карта не загрузилась      | Проверьте Google Maps и embed-URL; внешняя карта зависит от доступа к Google. Доступна ссылка открытия карты.                                                                  |

Изменение режима `NOTIFICATIONS_ENABLED` не возобновляет автоматически старые `disabled`, `failed` или `uncertain` задачи — это защита от неожиданных сообщений и дублей. Проверьте вручную и создавайте новые тестовые записи после настройки. Для регулярного обслуживания следите за статусами уведомлений и квотами; резервную копию базы можно выгрузить в защищённое место через `npx wrangler d1 export astana-beauty-db --remote --output backup.sql`. Такая копия содержит личные данные клиентов и не должна попадать в публичный репозиторий.
